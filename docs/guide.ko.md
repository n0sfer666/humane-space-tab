이 앱에는 작업할 자체 윈도우가 없습니다. 메뉴 막대에 머물며, 하는 일은 모두 단축키를
누르고 있는 동안 일어납니다.

![리본](images/ribbon.png)

## 처음 실행할 때

1. 설치합니다 — `brew install --cask n0sfer666/tap/humane-space-tab`, 또는 Releases에서
   디스크 이미지를 열어 **Humane Space Tab.app**을 Applications 단축 아이콘으로 끌어다
   놓고 실행합니다.
2. 내려받은 앱은 처음에는 열리지 않습니다. **시스템 설정 → 개인정보 보호 및 보안**을
   열고 맨 아래로 스크롤한 다음 **그래도 열기**를 누르고 다시 실행하십시오.
3. 앱은 시작하면서 **손쉬운 사용** 권한을 요청합니다. **시스템 설정 → 개인정보 보호 및
   보안 → 손쉬운 사용**에서 허용하십시오. 전환기는 몇 초 안에 동작하기 시작하며 다시
   실행할 필요는 없습니다.

메뉴 막대의 아이콘은 앱이 실행 중이라는 유일한 표시입니다. 동작할 때는 `⇄`, 동작하지 못할
때는 경고 삼각형이 나타납니다. macOS는 권한을 코드 서명에 묶어 두므로 업데이트할 때마다
권한을 다시 주어야 합니다.

## 앱 사이를 전환하기

**⌘**을 누른 채 **Tab**을 누릅니다. 무엇이 일어나는지는 얼마나 오래 누르고 있는지에
달렸습니다.

- **짧게 누르면** — 표시까지의 지연(기본값 120 ms)보다 짧으면 — 아무것도 보이지 않은 채
  바로 이전 앱으로 전환합니다. 손에 익은 그대로입니다.
- **⌘을 계속 누르고 있으면** **현재 데스크탑**의 앱들이 리본에 나타납니다. 최근에 쓴
  것이 앞쪽입니다. **Tab**을 한 번 더 누를 때마다 선택이 한 칸씩 움직입니다.

리본이 열려 있는 동안:

| 키 | 하는 일 |
|---|---|
| **Tab** | 한 칸 앞으로 |
| **⇧Tab** | 한 칸 뒤로 |
| **Escape** | 취소 — 아무것도 전환되지 않음 |
| **⌘** 놓기 | 선택한 앱으로 전환 |

선택된 앱은 더 크고 진하게 그려지며 아래에 이름이 붙는 아이콘입니다. 이웃한 아이콘은
흐려집니다. 앱이 다섯 개가 되면 리본은 캐러셀이 됩니다. 선택은 제자리를 지키고 아이콘이
그 아래로 돌기 때문에, 한 걸음은 눈에 언제나 같은 거리이고 목록에는 끝이 없습니다. 마지막
앱 다음에는 첫 번째 앱이 옵니다. 다섯 개 미만이면 아이콘은 저마다 제자리에 있고 선택만
움직입니다. 리본은 열 칸에서 더 커지지 않습니다.

아무것도 열려 있지 않은 데스크탑에서도 리본은 응답하여 그곳에 아무것도 없다고 알립니다.
키 입력을 시스템 전환기에 돌려주지 않습니다.

## 한 앱의 윈도우 사이를 전환하기

**⌘**을 누른 채 **`**(Tab 위의 키)을 누릅니다. 리본에는 맨 앞 앱의 윈도우가 나열됩니다.
현재 데스크탑에 있는 것만, 쌓인 순서대로, 각자의 제목과 함께 나옵니다. 동작은 같습니다.
`⇧`는 방향을 뒤집고, Escape는 취소하며, **⌘**을 놓으면 그 윈도우가 앞으로 나옵니다.

시스템 단축키는 모든 데스크탑의 윈도우를 한꺼번에 세기 때문에 다른 데스크탑으로 넘어가게
됩니다. 이 단축키는 그럴 수 없습니다. 여기에 없는 윈도우는 목록에도 없으므로 데스크탑이
바뀌는 일도, Dock에 넣어 둔 윈도우가 되살아나는 일도 없습니다.

## 마우스

리본이 열려 있는 동안 포인터는 리본 위에서 동작합니다.

- 아이콘 위에서 **마우스를 움직이면** 그 아이콘이 선택됩니다. 리본이 열린 자리에 그저 놓여
  있던 포인터는 움직이기 전까지 아무것도 바꾸지 않습니다.
- 아이콘을 **클릭하면** **⌘**을 놓기를 기다리지 않고 곧바로 전환합니다.
- 리본 위에서 **스크롤하면** 선택이 한 칸씩 움직입니다.

## 설정

메뉴 막대 아이콘 → **설정…**에서 엽니다.

![설정](images/settings.png)

| 설정 | 무엇인지 |
|---|---|
| **앱** | 리본을 여는 단축키. 필드를 클릭하고 조합을 입력하거나, **기본값으로 복원**으로 `⌘Tab`으로 되돌립니다. |
| **맨 앞 앱의 윈도우** | 두 번째 단축키. 기본값은 `` ⌘` ``입니다. |
| **리본을 표시할 화면** | 키보드 포커스가 있는 화면, 또는 포인터가 있는 화면. |
| **언어** | 인터페이스의 언어. **시스템**은 macOS를 따릅니다. 앱이 담고 있는 언어는 각자의 이름으로 표시됩니다. 고르면 윈도우가 곧바로 다시 그려집니다. |
| **표시까지의 지연** | 리본이 나타나기까지 단축키를 눌러야 하는 시간 — 0에서 500 ms. `0`이면 즉시 나타납니다. |
| **로그인 시 열기** | 앱을 macOS에 로그인 항목으로 등록합니다. |
| **앱이 아니라 윈도우 사이를 전환** | `⌘Tab`이 윈도우를 나열하게 됩니다. Windows나 Linux와 같은 방식입니다. 기본값은 끔이며, 켜면 한 편집기의 두 도큐멘트가 두 항목이 됩니다. |
| **데스크탑의 비공개 레이어 사용** | 비공개 레이어는 Dock에 넣어 둔 윈도우가 어느 데스크탑에 속하는지 알지만 공개된 규격이 아닙니다. 끄면 앱은 화면에 있는 윈도우만 봅니다. |

앱은 열다섯 개 언어를 담고 있습니다 — 영어, 러시아어, 독일어, 프랑스어, 스페인어,
포르투갈어(브라질), 이탈리아어, 네덜란드어, 폴란드어, 터키어, 우크라이나어, 일본어,
한국어, 그리고 두 가지 중국어 문자 — 그 밖의 언어에서는 영어로 응답합니다. 이 안내서의
항목 이름은 한국어로 인용합니다.

단축키에는 누르고 있을 수식 키가 필요하며, 설계상 지킬 수 없는 것은 레코더가 거부합니다.
수식 키가 없는 조합, 이미 **⇧**를 포함한 조합(그것은 반대 방향입니다), **Escape**, `⌘Q`,
`⌘W`가 그렇고, 어느 경우였는지도 알려 줍니다. 단축키는 현재 입력 소스의 키로 그려집니다.

## 외관

**설정…**의 두 번째 탭은 프로파일에 담기는 리본의 모습입니다. **기본값**은 내장된 것이라
편집할 수 없습니다. **복제**하면 편집할 수 있는 사본이 생기고, **이름**으로 자기 이름을
붙일 수 있습니다. 내장된 것 외에 다섯 개까지 둘 수 있으며, 사용 중인 프로파일을 삭제하면
**기본값**이 다시 사용됩니다.

| 설정 | 무엇인지 |
|---|---|
| **아이콘 크기** | 아이콘이 그려지는 최대 크기. 빽빽한 리본은 화면에 맞추려고 그보다 작게 줄입니다. |
| **아이콘 불투명도** | 아이콘을 얼마나 진하게 그릴지. 100 %가 최대이며, 그보다 낮춰도 선택 항목은 여전히 도드라집니다. 사전 설정이 선택되지 않은 것들을 흐리게 하기 때문입니다. |
| **리본 여백** | 아이콘과 리본 가장자리 사이의 공간. 아이콘에 대한 비율입니다. |
| **아이콘 사이 간격** | 두 아이콘 사이의 공간. 같은 비율로 지정합니다. |
| **모서리 반경** | 리본 모서리가 얼마나 둥근지. |
| **아이콘 테두리**, **테두리 여백** | 아이콘 둘레에 그리는 선과 아이콘까지의 거리. |
| **배경** | **유리**는 시스템 자체의 재질입니다. **어둡기**는 그것을 어둡게 하며, `0`에서는 리본이 맨 유리가 되어 데스크탑이 그대로 비쳐 보입니다. **투명**과 **윈도우 배경색**은 재질이 없고 **불투명도**만으로 정해집니다. |
| **캐러셀** | **선택 항목 아래에서 줄 돌리기**를 끄면 줄은 그대로 있고 화면에 맞게 줄어듭니다. 켜면 **칸 수**가 몇 개의 아이콘 안에서 도는지를 정합니다(5–12). |
| **선택** | 선택된 아이콘을 무엇으로 구별할지. 시스템 전환기와 같게, 크게, 혼자 돋보이게, 또는 테두리로. |

숫자마다 슬라이더와 같은 값을 보여 주는 필드가 있고, 범위는 서로에게 응답합니다. 간격을
넓히면 여백이 자랄 자리가 그만큼 줄어듭니다. **예시 보기…**는 고른 수만큼의 예시 앱으로
리본을 4초 동안 그려 보여 주며, 지금 있는 데스크탑을 건드리지 않습니다.

| **입력 모니터링 열기…** | macOS가 키 입력을 붙들고 있을 때(아래 참조) |

| **앱과 윈도우 목록 복사** | 항상 — 현재 데스크탑의 앱 목록을 클립보드에 복사합니다. 버그 리포트에 첨부할 것이 이것입니다 |
| **Humane Space Tab 종료** | 항상 |

## 무언가 잘못되었을 때

**메뉴 막대에 아이콘이 없습니다.** 노치 왼쪽에 빈자리가 없는 메뉴 막대는 아이콘을
떨어뜨립니다. macOS는 넣을 자리가 없는 상태 항목을 그리지 않고, 앱 쪽에서 그 자리를
차지할 방법도 없습니다. 자리를 비우거나 Finder 또는 Spotlight에서 앱을 다시 여십시오. 두
번째 실행은 두 번째 사본이 아니라 설정을 엽니다.

**macOS가 키 입력을 붙들고 있다고 아이콘이 알립니다.** **시스템 설정 → 개인정보 보호 및
보안 → 입력 모니터링**에 남은 옛 항목이 앱을 막고 있습니다. 그 항목을 **−**로 삭제하고
— 앱에 필요한 것은 권한이 아니라 거부가 없는 상태입니다 — 앱을 다시 클릭하십시오. 탭은
다시 실행하지 않고도 새로 만들어집니다.

**키 입력을 붙잡고 있는 앱 이름이 메뉴에 표시될 때.** 암호 입력란에 포커스가 있는 동안 macOS는
*보안 입력*을 켜며, 그동안에는 이 앱을 포함해 어떤 앱도 키 입력을 받지 못합니다. 보통은 입력란을
벗어나면 끝나지만, 오래 지속된다면 어떤 앱이 해제하지 않은 것입니다. 이름은 macOS가 이를 귀속한
대상입니다. 화면을 잠갔다가 다시 해제하면 풀립니다.

**`⌘Tab`이 여전히 시스템 전환기입니다.** 권한이 없거나 이전 빌드에 주어진 것입니다.
**손쉬운 사용 열기…**를 사용하고, 목록에 앱 항목이 이미 있다면 **−**로 지운 다음 다시
허용하십시오.

**‘로그인 시 열기’가 유지되지 않습니다.** macOS가 등록을 거부하면 그 이유를 체크상자
아래에 자기 말로 적어 둡니다. 흔한 이유는 시스템이 알아보지 못하는 빌드입니다. 로컬
빌드는 저마다 ad-hoc 서명을 가지므로 어제 사본이 한 등록은 오늘 사본의 것이 아닙니다.
`/Applications`에 있는 사본에서 껐다가 다시 켜십시오.

## 앱이 볼 수 있는 것

앱은 손쉬운 사용이라는 넓은 권한을 가지고 있으며, 그것으로 하는 일은 의도적으로 아주
적습니다. 네트워크 코드는 전혀 없고, AppleEvents도 플러그인도 없습니다. 키 입력은 당신의
단축키와 맞는지만 확인합니다. 윈도우 제목은 윈도우 전환이 켜져 있는 동안, 그리기 위해서만
읽습니다. 포인터는 리본 자체의 패널 위에서만 보입니다. 화면 기록 권한은 결코 요청하지
않으며, 윈도우 미리보기를 보여 주지 않는 이유가 그것입니다. 전체 위협 모델은
[S00](specs/S00-threat-model.md)에 있습니다.
